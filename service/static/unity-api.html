OCI S3 Credential Lifecycle Manager · API v0.2.0

Unity connector integration guide

Use a bearer-authenticated HTTP request for automatic bucket access, or obtain a credential lease when your connector needs direct S3 access.

Automatic bucket access · recommended HTTP path

After onboarding and obtaining a service JWT as described below, send the bucket and operation. The backend selects a profile that the connector identity and token scopes already authorize. Object Storage applies the backend workload identity’s bucket-restricted IAM permissions.

POST /v1/bucket-operations
Authorization: Bearer <access_token>
Content-Type: application/json

{"bucket":"lcm-live-v2-sales","operation":"LIST","limit":20}

The result includes selected_profile, objects and next_start. To read an object:

{"bucket":"lcm-live-v2-sales","operation":"GET","key":"quarterly/revenue.csv"}

GET returns content_base64, size and etag. Decode base64 to obtain the original bytes. To create an object with a write-authorized connector:

{"bucket":"lcm-live-v2-sales","operation":"PUT","key":"automation/example.txt","content_base64":"SGVsbG8K"}

PUT is create-only by default. To replace an existing object, supply if_match with the ETag from GET or LIST. An existing object or stale ETag returns HTTP 412; inspect it before retrying. A timeout can mean an operation completed: check the object and ETag before deciding whether to retry.

This path creates no Customer Secret Key, lease, Vault replay secret or expiration schedule. OCI SDK workload credentials are managed internally and request resources are closed after the operation. The four-slot lease pool does not limit this path. Existing lease cleanup continues separately.

Initial limits: GET/PUT objects up to 512 KiB; LIST up to 100 objects per page. Supply LIST prefix and start (the prior next_start) as needed. No DELETE, arbitrary endpoint, streaming, range reads or multipart support. This is a custom bearer HTTP API, not a native S3 endpoint. Actual Unity-engine integration remains outstanding.

The demo automatically lists the first authorized bucket after sign-in. Its Automatic bucket access controls also let you read or create an object without selecting a profile or requesting credentials.

1. Onboard your connector

Ask the deployment operator for a dedicated Identity Domain confidential OAuth client with client_credentials enabled, the approved API scopes, and a backend identity-to-profile mapping. The demo UI’s connector registration does not automatically authorize a new Unity client. Share the client secret through your secret manager, never through this page or source control.

2. Obtain a service access token

Use HTTP Basic client authentication and form-encoded parameters. Load credentials securely on your backend. Do not use an OCI Console Auth Token, your OCI API signing key, or a user ID token as the bearer token.

POST /oauth2/v1/token
Authorization: Basic <base64(client_id:client_secret)>
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&scope=<URL-encoded-full-scope-URI>

Keep the returned access_token server-side. API Gateway validates it. The backend then checks the connector’s approved profile mapping and lease ownership.

3. Optional direct-S3 path: create a credential lease

POST /v1/leases
Authorization: Bearer <access_token>
Content-Type: application/json
Idempotency-Key: 9b35fbb8-954c-46de-b48a-0bcf88637db4

{
  "scope_profile": "sales-read",
  "ttl_seconds": 900,
  "client_request_id": "unity-query-123"
}

A new lease returns 201. An authorized replay returns 200. The following values are illustrative placeholders:

{
  "lease_id": "e751b64f-dac0-438e-b4d4-651c857a0f96",
  "status": "ACTIVE",
  "access_key_id": "<issued-access-key>",
  "secret_access_key": "<issued-secret>",
  "endpoint": "https://<namespace>.compat.objectstorage.us-ashburn-1.oci.customer-oci.com",
  "region": "us-ashburn-1",
  "scope_profile": "sales-read",
  "expires_at": "<UTC ISO-8601 timestamp>",
  "expiry_mode": "managed_key_deletion"
}

TTL is 300–3600 seconds, default 900, measured from IAM key creation. Issuance and credential propagation consume part of that time. The backend reserves a service user, creates its key, confirms the expiration schedule and stores a bounded retry response before delivering credentials.

4. Access the bucket using S3

Use the returned endpoint and region with AWS Signature V4 and path-style addressing. There is no AWS session token. The service JWT authenticates Lifecycle API calls; it is not sent to Object Storage.

import boto3
from botocore.config import Config

s3 = boto3.client(
    "s3",
    endpoint_url=lease["endpoint"],
    region_name=lease["region"],
    aws_access_key_id=lease["access_key_id"],
    aws_secret_access_key=lease["secret_access_key"],
    config=Config(signature_version="s3v4",
                  s3={"addressing_style": "path"}),
)
result = s3.list_objects_v2(Bucket=profile["bucket"], MaxKeys=1)

Use the bucket from the selected profile returned by /v1/config. New keys may require propagation time before S3 accepts them. Use bounded retries; never extend the recorded deadline or mint repeated leases to hide propagation failures.

5. Revoke and confirm cleanup

DELETE /v1/leases/<lease_id>
Authorization: Bearer <current-access-token>

GET /v1/leases/<lease_id>
Authorization: Bearer <current-access-token>

DELETE returns an empty 202 when revocation is requested, or 204 if already revoked. Poll GET until status is REVOKED. Refresh the service JWT if necessary; the connector issuer and subject must still match the lease owner and its scope must authorize the profile.

Early revocation or expiration deletes the owned IAM key, cleans up its schedule and replay secret, updates ADB, and releases the pool slot. The service user, bucket and data remain. Failures stay REVOKE_PENDING for retry. Always attempt early revocation in a finally block; expiration cleanup is the fallback.

Retries and errors

While POST /v1/leases is running, poll GET /v1/lease-requests/<idempotency-key-UUID> for owner-bound progress. A 404 can mean the reservation is not committed yet. Progress never contains credentials. The UI opens the credential panel immediately and shows actual stages while awaiting the create response.

Persist one UUID idempotency key per intended lease and reuse it with an identical body after uncertain network outcomes. Do not create a new key for every retry. Credential responses can be replayed for at most 60 seconds; metadata GET never returns the secret.

Status / codeConnector action
400 · INVALID_INPUT / INVALID_IDEMPOTENCY_KEYFix the request; the idempotency header must contain a UUID.
401Refresh the token and retry the same request once. Check audience and issuer if it persists. Gateway errors may have a different body.
403 · PROFILE_FORBIDDEN / NOT_OWNERCheck scopes, backend mapping and connector identity. Do not retry unchanged.
409 · ISSUANCE_PENDINGBack off and retry with the same key and body.
409 · IDEMPOTENCY_CONFLICTThe same key was used with a different body. Do not overwrite its meaning.
409 · CREDENTIALS_NOT_REPLAYABLEUse the returned lease ID to inspect/revoke the original lease. Request a new lease only as a deliberate replacement.
422 · UNSUPPORTED_SCOPEChoose a profile returned by GET /v1/config.
429 · POOL_EXHAUSTED / RATE_LIMITEDHonor Retry-After. Bound concurrency; an idle slot in another profile is not interchangeable.
503Back off. Preserve the idempotency key; if a lease ID is supplied, inspect that lease. Cleanup or dependency health may be blocking issuance.

Backend errors use {"error":{"code":"…","correlation_id":"…","lease_id":"…"}}; lease_id is optional. Log correlation IDs and status codes, never tokens, credentials, Authorization headers, or raw issuance responses.

Endpoints and implementation checklist

  • GET /v1/config — authorized profiles and TTL bounds.
  • POST /v1/leases — create or replay credentials.
  • GET /v1/leases/{lease_id} — metadata and cleanup status.
  • DELETE /v1/leases/{lease_id} — early revocation.
  • GET /v1/leases — up to 100 recent leases for the connector.

Metrics, audit, test-setup and lease-test endpoints support demo diagnostics. The /auth/* and /connector/* routes belong to the browser demo and are not the server-to-server integration API.

  • Store OAuth client secrets in a secret manager; cache JWTs only until their expiry.
  • Keep S3 secrets in memory and bound credential caching to the lease deadline.
  • Stop using credentials at the deadline even if a later S3 request might succeed.
  • Renew by creating a distinct lease; there is no extend/renew endpoint. Allow spare pool capacity for overlap.
  • Test retries, ownership errors, pool exhaustion, propagation and cleanup with the actual Unity engine.

Current acceptance limits

This is a live OCI test deployment, not production-ready. Actual Unity Catalog/query-engine compatibility remains unaccepted. Customer Secret Keys do not have native STS expiry: IAM deletion and S3 enforcement can be delayed. Earlier tests observed successful reads 237.995 seconds after the deadline despite confirmed key absence. Requested deadlines are not guaranteed hard access cutoffs; no production issuance-latency guarantee has been established.
